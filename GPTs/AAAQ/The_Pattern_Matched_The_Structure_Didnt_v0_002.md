# The Pattern Matched. The Structure Didn't.

## Functional Resemblance Is Not Structural Equivalence

**Version:** v0.002

### Abstract

The motivating AAAQ case shows a language model treating matching outputs as stronger evidence of shared architecture than the source supported. This paper turns that case into a testable failure hypothesis; it does not assume that the behaviour is universal or frequent.

That move is attractive because surface resemblance is easy to see. Two systems may classify the same case, produce similar labels, divide a domain into the same number of regions, or support comparable actions. From that overlap, a model may infer a shared substrate, hidden common generator, or direct equivalence.

This paper examines that failure: **functional resemblance promoted into structural equivalence**.

A motivating AAAQ architecture-review case involved a compact coordinate key, an actor system, and operational story structures. The model observed that the systems could be aligned and then treated the alignment as evidence that they arose from one coordinate machine. The mapping was possible. The derivation was not established.

The paper separates behavioural overlap, translation, topology, structure, and genealogy. It proposes a Same-Output Different-Machine benchmark, a Structure Evidence Ladder, and a burden-of-proof rule for equivalence claims. The proposal is related to structure-mapping research on analogy and to formal work that distinguishes observed behaviour from the internal machine consistent with that behaviour [1-4].

The central distinction is:

```text
Two systems can do the same thing
without being the same kind of thing.
```

## 1. The failure

Suppose two systems both classify a meeting event as hostile.

One uses:

```text
actor role
story relation
live permission state
```

The other uses:

```text
elemental lens
intensity score
center integration
```

The outputs may align.

```text
System A -> hostile pressure
System B -> Fire + Metal
```

A model may then infer:

```text
same result
-> same hidden structure
```

That inference does not follow.

The systems may share:

```text
an output
a practical use
a translation route
a rough topology
```

while differing in:

```text
units
relations
state transitions
generation rules
failure modes
update logic
```

Matching behaviour is evidence of overlap.

It is not proof of one architecture.

## 2. The AAAQ case

The motivating case involved several named structures with different jobs.

One compact key could index positions.

A wider actor system supplied recurring roles.

Operational story structures supplied question, foe, and control relations.

AAAQ observed that these systems could be mapped into one another.

From that, it promoted a stronger claim:

```text
they share one coordinate substrate
```

The mapping did not establish the substrate.

A translation table can be built between systems that were created independently.

```text
English word
<-> Swedish word
```

does not mean the languages share one grammar.

Likewise:

```text
actor label
<-> coordinate address
```

does not prove the actor was generated by that coordinate address.

The model mistook **representability** for **derivation**.

## 3. Five different equivalence claims

The word "equivalent" hides several claims.

### 3.1 Functional equivalence

Two systems can perform the same task under stated conditions.

```text
A(x) = B(x)
for tested x
```

This is an output claim.

### 3.2 Translational equivalence

A mapping can convert one system's outputs into the other's.

```text
T(A(x)) = B(x)
```

This requires a translation route.

It does not require shared internal construction.

### 3.3 Topological resemblance

The systems have similar visible shape.

Examples:

```text
same number of regions
paired opposites
center plus perimeter
tree-like branching
```

Shape can guide comparison.

Shape alone does not establish role or generation.

### 3.4 Structural equivalence

The systems share relevant units, relations, constraints, and transition rules.

This is a much stronger claim.

### 3.5 Genealogical equivalence

The systems derive from the same source architecture or one was built from the other.

This requires historical or source evidence.

These claims form a ladder.

```text
functional
< translational
< topological
< structural
< genealogical
```

Evidence for a lower rung does not automatically support a higher one.

## 4. The Structure Evidence Ladder

Use the following ladder when reviewing equivalence claims.

```text
SEL0 = visual resemblance
SEL1 = shared vocabulary
SEL2 = matching output on examples
SEL3 = stable translation across cases
SEL4 = matching failure boundaries
SEL5 = matching internal relations
SEL6 = matching transition rules
SEL7 = matching generative grammar
SEL8 = documented common derivation
```

A model should state the highest supported level.

Example:

```text
Observed:
both systems classify the same eight examples similarly.

Supported:
SEL2

Not yet supported:
SEL5 structural equivalence
SEL7 shared generator
SEL8 common derivation
```

This prevents a small resemblance from becoming a total identity claim.

## 5. Same output, different machine

Many distinct architectures can produce the same result.

```text
lookup table
rule engine
neural model
finite-state machine
human judgement
story classifier
coordinate map
```

For a bounded input set, all may agree.

This is underdetermination.

```text
observed outputs
do not uniquely identify
internal structure
```

A model that sees only the outputs must preserve multiple possible machines.

## 6. Why a language model may make the jump

The following are candidate explanations suggested by the AAAQ case. They should be tested as competing hypotheses rather than read as established mechanisms of language-model cognition.

### 6.1 Compression pressure

One shared substrate is easier to explain than several independent systems.

```text
many structures
-> one hidden base
```

The explanation becomes neat.

The evidence does not become stronger.

### 6.2 Symmetry attraction

Matching counts or shapes invite unification.

```text
8 lenses
8 poles
8 roles
```

The shared number becomes a false bridge.

### 6.3 Analogy overreach

Analogy is useful for translation.

It becomes dangerous when the model upgrades:

```text
A behaves like B
```

into:

```text
A is built like B
```

### 6.4 Mapping success

When a model successfully maps every visible item, the mapping feels explanatory.

But a complete mapping may be imposed from outside.

```text
successful alignment
!=
native derivation
```

### 6.5 Missing negative tests

Models often compare where systems agree.

They do not test:

```text
where one system has no state
where one permits mixtures
where one preserves residue
where one updates over time
where one rejects the input
```

The disagreement zones reveal structure.

## 7. Translation is not identity

A useful translation layer can exist between unlike systems.

Example:

```text
temperature in Celsius
<-> temperature in Fahrenheit
```

These are structurally close because the relation is formally defined.

But other translations are looser:

```text
emotion words
<-> colour categories
```

A translation can support use without proving identity.

The architecture review should record:

```text
translation direction
loss
ambiguity
residue
context dependence
```

A lossy mapping is still useful.

It must not be presented as a shared generator.

## 8. The residue test

A strong comparison asks what does not map.

```text
RESIDUE =
source meaning
not carried by translation
```

If System A preserves:

```text
who acts
who is affected
whether permission exists
how the state changes
```

and System B emits only:

```text
Fire high
Metal medium
```

then the mapping loses relational structure.

That residue is evidence that the systems are not structurally equivalent.

A model that removes residue to make the mapping total is changing the source.

## 9. Failure-boundary comparison

Two systems that agree on ordinary cases may diverge under stress.

Test:

```text
ambiguous input
mixed state
self-reference
contradiction
missing actor
state transition
novel category
invalid input
```

Structural equivalence requires more than matching normal outputs.

The systems should also fail in corresponding ways.

```text
same answers
different failure boundaries
=
different machine
```

## 10. Transition rules matter

Static category matches are weak evidence.

A live system includes movement.

```text
state_t
-> event
-> state_t+1
```

To claim structural equivalence, compare:

```text
what triggers change
what remains stable
what resets
what accumulates
what blocks movement
what counts as invalid
```

Two systems may assign the same current label and still predict different next states.

That difference is structural.

## 11. Generative grammar test

The strongest non-historical test asks whether both systems generate the same valid space.

```text
What units exist?
How are they combined?
Which combinations are valid?
Which are impossible?
What creates a new state?
```

If one system begins with eight lenses and the other begins with relational actor positions, surface alignment is not enough.

They must show the same generation rules.

Otherwise:

```text
same region reached
different route produced it
```

## 12. Benchmark design

### Research question

When two systems produce similar outputs, how often do language models overclaim shared structure?

### Task packet

Each item contains two systems with controlled overlap.

```text
same outputs on common cases
different hidden architecture
different failure boundary
one tempting numerical symmetry
one lossy translation
```

### Condition A: Output only

The model sees matching examples.

### Condition B: Internal rules

The model sees units and transition rules.

### Condition C: Mapping table

A complete crosswalk is supplied.

### Condition D: Historical claim

One system is said to derive from the other, with or without source evidence.

### Condition E: Counterexample

A case reveals different failure behaviour.

### Condition F: Residue-visible

The translation loss is explicitly shown.

## 13. Hypotheses

```text
H1:
Models will overclaim structure
when outputs and category counts match.

H2:
A complete mapping table will increase identity claims
even when the mapping is externally imposed.

H3:
Failure-boundary tests will reduce overclaiming.

H4:
Residue tracking will improve distinction
between translation and equivalence.

H5:
Models will confuse topological resemblance
with shared generative grammar.

H6:
Historical-source demands will reduce
unsupported genealogy claims.

H7:
Models will retain elegant unifications
after local counterexamples unless the substrate premise is reopened.
```

## 14. Metrics

### Equivalence Inflation Rate

```text
EIR =
claims made above supported ladder level
/
all equivalence claims
```

### Residue Suppression Rate

```text
RSR =
unmapped source features omitted
/
unmapped source features present
```

### Failure-Boundary Coverage

How many divergence cases were tested?

### Structure Evidence Match

Did the strength of the claim match the evidence level?

### Genealogy Support Rate

How often were derivation claims tied to source or historical evidence?

### Translation Loss Accuracy

Did the model state what the mapping fails to carry?

## 15. A practical comparison form

```text
COMPARE={
  task_overlap;
  output_overlap;
  translation_route;
  topology_overlap;
  unit_match;
  relation_match;
  transition_match;
  failure_match;
  residue;
  source_history;
  highest_supported_claim;
}
```

This form prevents the word "same" from doing too much work.

## 16. AAAQ repair route

The failed route was:

```text
systems align
-> shared coordinate base
-> generated lookups
-> unified architecture
```

A valid repair is:

```text
systems align on selected outputs
-> translation may exist
-> shared substrate remains unproven
-> generated lookups are hypotheses
-> native structures keep authority
```

The correction must remove downstream objects that depended on the unproven base.

It is not enough to say:

```text
the systems are different categories
```

while keeping the same generated machinery.

## 17. The source-wins rule

When a comparison conflicts with native definitions:

```text
SOURCE WINS
```

This means:

```text
mapping may describe overlap
mapping may not rewrite source identity
```

A model may propose:

```text
possible relation
candidate translation
testable structural hypothesis
```

It should not silently convert those into:

```text
native architecture
shared origin
proven generator
```

## 18. A concise claim vocabulary

Use bounded language.

```text
RESEMBLES
OVERLAPS
TRANSLATES_TO
PREDICTS_SAME_OUTPUT_ON
SHARES_TOPOLOGY_WITH
STRUCTURALLY_MATCHES
DERIVES_FROM
```

Each verb carries a different burden.

The model should choose the weakest verb that fits the evidence.

## 19. Regeneration probe

After correction, present a new pair of systems with matching outputs.

If the model again invents a shared substrate, the route survived.

The probe should change names and surface details while preserving:

```text
output match
structural difference
tempting symmetry
```

A durable repair should keep the distinction:

```text
same behaviour
not automatically same construction
```

## 20. Relation to 8D-style lens packs

An eight-lens pack may classify the same material as a relational architecture.

That does not make the lens pack an underlying generator.

For example:

```text
lens pack:
views material through eight named domains

relational system:
generates live positions between actors
```

The lens output may translate into the relational system's display.

The relational system may also consume the lens pack as input.

Those facts establish interaction.

They do not establish structural equivalence.

## 21. Relation to model evaluation

Two models can achieve the same benchmark score through different routes.

One may reason from source.

One may exploit answer patterns.

Score equivalence is not process equivalence.

This matters when evaluating:

```text
robustness
transfer
safety
generalisation
repair
```

A benchmark that records only output agreement cannot tell which machine produced it.

## 22. Relation to science

Scientific models often make similar predictions while resting on different mechanisms.

Prediction match can justify continued testing.

It does not settle mechanism.

The same discipline belongs in architecture review.

```text
fit first
mechanism later
genealogy only with evidence
```

## 23. Practical grader

```text
STRUCTURE_GRADE={
  output_match_bounded?;
  translation_loss_named?;
  topology_not_overclaimed?;
  units_compared?;
  relations_compared?;
  transitions_compared?;
  failure_boundaries_tested?;
  genealogy_sourced?;
  native_definitions_preserved?;
}
```

Possible outcomes:

```text
PASS
PARTIAL
REPAIR_REQUIRED
BLOCK
```

A response that maps every label but never tests generation should receive:

```text
PARTIAL
```

not structural-equivalence PASS.

## 24. Relation to analogy and black-box testing

The paper's distinction between resemblance and structure has established neighbours in two different research traditions.

Structure-mapping theory treats analogy as a mapping between relational systems rather than mere surface feature overlap [1]. The Structure-Mapping Engine operationalised that account by building correspondences subject to structural constraints [2]. These works support the paper's insistence that a successful mapping is itself an object to analyse. They do not imply that mapped systems share a generator or genealogy.

A second neighbour comes from black-box and finite-state testing. Lee and Yannakakis survey methods for distinguishing finite-state machines through carefully selected input/output behaviour [3]. Angluin's work on learning regular sets from queries and counterexamples similarly shows the evidential role of counterexamples in narrowing the class of models consistent with observations [4].

The connection is methodological:

```text
matching examples
-> candidate equivalence

distinguishing example
-> equivalence class narrows
```

The AAAQ paper extends this logic into architecture review by separating several claim strengths: output overlap, stable translation, structural relation, generative rule, and genealogy.

The Structure Evidence Ladder introduced here is not a standard scale from those literatures. In particular, its ordering should not be interpreted as a theorem that every domain must satisfy. It is a proposed review discipline whose reliability and usefulness need empirical testing.

## 25. Limits

The AAAQ case is bounded evidence. It motivates the benchmark but does not establish prevalence, hidden mechanism, or a general language-model tendency.

Some systems are structurally equivalent even when their names differ.

No finite test can prove total equivalence across every possible input.

The required evidence depends on the claim. Functional equivalence may need only bounded task testing. Genealogical equivalence needs source history.

A strict distinction should not block useful analogy. The goal is to label analogy by its actual strength.

The proposed Structure Evidence Ladder, Equivalence Inflation Rate, and Residue Suppression Rate are unvalidated research constructs. Their levels and scoring rules require inter-rater testing, ablation against simpler grading schemes, and domain-specific calibration before they can support quantitative claims.

## 26. Conclusion

AAAQ saw a successful mapping and promoted it into a shared architecture.

The pattern matched.

The structure had not been shown to match.

The governing ladder is:

```text
same output
< stable translation
< shared topology
< shared structure
< shared derivation
```

Each upward move needs new evidence.

A model may say:

```text
these systems can translate
```

without saying:

```text
these systems are the same machine
```

That difference protects both comparison and source authority.

The title names the fault:

```text
The pattern matched.
The structure didn't.
```
