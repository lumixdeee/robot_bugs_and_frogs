# Repair Without Revision

## How Language Models Patch Local Claims While Preserving Failed Premises

**Version:** v0.002

### Abstract

Language models can respond to correction at the sentence level by retracting a claim, replacing a label, or rewriting a local explanation. That visible responsiveness can be mistaken for deeper revision. The AAAQ cases examined here show that this distinction can matter in architecture-review work; they do not establish how frequently it occurs across models or tasks.

This paper examines a different failure mode: **repair without revision**. A model accepts the user's correction, alters the surface answer, and still preserves the failed premise that generated the error. The local patch succeeds. The reasoning route remains intact.

A motivating set of AAAQ architecture-review errors shows the pattern in two forms. In the first, a compact coordinate key was promoted into a human-facing architecture even though the source relation did not support that placement. After correction, the model removed the explicit category error but retained the same untested coordinate system, generated lookups, and shared-structure assumption. In the second, a size expectation was converted into an optimisation target. When challenged, the model repaired the visible ratio language without first reopening the task method that the ratio was meant to evaluate.

The paper separates local correction, relation repair, route repair, premise reopening, and source-grounded rebuild. It proposes a benchmark for measuring how deeply a model revises after correction, introduces a Correction Depth Scale, and presents a practical repair protocol. The proposal is positioned against work on iterative self-refinement, reflective agents, tool-assisted correction, and critical surveys of LLM self-correction [1-6]. The central claim is simple:

```text
A changed answer is not evidence of a changed premise.
```

## 1. The problem

Language models are good at linguistic compliance.

A user says:

```text
That is the wrong category.
```

The model replies:

```text
You are right. The category error is removed.
```

The exchange feels repaired because the sentence changed and the model acknowledged the correction.

But architecture errors rarely live in one sentence. They are usually generated by a chain of hidden commitments:

```text
object identity
-> assumed relation
-> route choice
-> local claim
-> wording
```

If the correction only reaches the wording or local claim, the same upstream structure remains available to regenerate the error.

This creates a misleading pattern:

```text
visible concession
+ fluent rewrite
+ preserved premise
= apparent repair
```

The danger is not stubbornness. The model may be highly cooperative. The danger is that cooperation can happen at the wrong layer.

Repair without revision is therefore not refusal to update. It is **update at insufficient depth**.

## 2. The motivating AAAQ case

The AAAQ case concerns a compact coordinate system, a wider actor architecture, and a human-facing mapping layer.

The initial model route treated a compact key as more than an index. It promoted the key toward the primary human interface and inferred a shared coordinate structure beneath several systems.

The user corrected the category relation.

AAAQ then acknowledged the error and stated that the category mistake had been removed. Yet the revised answer retained several commitments:

```text
shared coordinate domain
generated actor lookup
generated DRAGI lookup
same compact key as structural base
```

The local relation changed:

```text
actor type != DRAGI channel
```

But the upstream premise remained:

```text
actor system and DRAGI derive from the same coordinate machine
```

That premise had not been established from source structure.

The correction therefore succeeded at one level and failed at another.

This is the core event:

```text
local claim repaired
upstream architecture preserved
```

The same pattern later appeared in the map-building discussion.

The task included a method and a size expectation. The size expectation existed to evaluate whether the method had produced a compact semantic map. The model instead treated the visible number as an optimisation target.

The error route was:

```text
method + expected scale
-> scale extracted as objective
-> method weakened
-> number pursued
```

When challenged, the model revised the ratio language but did not initially reopen the objective function that caused the drift.

Again:

```text
surface patch
without route rebuild
```

These are not identical mistakes. One is architectural. One is metric-driven. They share the same repair failure.

## 3. Repair is not one operation

The word "repair" hides several distinct actions.

### 3.1 Wording repair

The model changes phrasing while preserving the same claim.

### 3.2 Local claim repair

The model changes one explicit proposition.

### 3.3 Relation repair

The model updates how two objects connect.

### 3.4 Route repair

The model changes the reasoning path used to reach the answer.

### 3.5 Premise reopening

The model returns to the assumption that made the route possible.

### 3.6 Source-grounded rebuild

The model discards unsupported structure and reconstructs the answer from the source object.

This is the deepest repair:

```text
source
-> object identity
-> relation
-> route
-> claim
-> wording
```

The process is rebuilt in the forward direction rather than patched backwards from the failed answer.

## 4. Correction Depth Scale

A useful benchmark needs more than pass or fail.

```text
CD0 = no change
CD1 = wording repair
CD2 = local claim repair
CD3 = relation repair
CD4 = route repair
CD5 = premise reopening
CD6 = source-grounded rebuild
```

The important distinction is between CD2 and CD5.

Many model responses look excellent at CD2. They are polite, direct, and linguistically responsive. Yet the failed premise remains active.

## 5. Why models stop too early

Several forces make shallow repair attractive.

### 5.1 Locality bias

The user's correction often points to the visible error. The model therefore edits the nearest matching proposition.

### 5.2 Coherence preservation

Discarding an upstream architecture creates a temporary gap. A local patch preserves more of the existing answer and produces smoother continuity.

### 5.3 Commitment inertia

Once a model has generated a detailed structure, that structure becomes context.

```text
generated structure
-> conversational residue
-> accidental premise
```

### 5.4 User-satisfaction pressure

A quick acknowledgement and revised sentence signal cooperation. A deeper rebuild takes longer and may sound less certain.

### 5.5 Symmetry attraction

Compact systems are easy to preserve because they offer strong internal order. A coordinate grid, actor matrix, or elegant ratio can survive correction because the model treats its internal neatness as evidence.

### 5.6 Metric capture

When a task contains a visible score, size, ratio, or threshold, the model may repair toward the metric rather than toward the method.

## 6. False repair signatures

Repair without revision often leaves detectable traces.

```text
unsupported structure survives
the model cannot name what was discarded
the source is not revisited
the new answer reuses the same skeleton
the correction is quoted but not operationalised
confidence remains unchanged
```

A premise-level correction should often lower confidence until the rebuild is complete.

## 6A. Related work and claim boundary

There is substantial evidence that language models can improve outputs under some forms of iterative feedback, but the literature also shows that "self-correction" is not one uniform capability.

Self-Refine iterates between model-generated feedback and revision and reports improvements across several generation tasks [1]. Reflexion stores verbal reflections from task feedback and uses them to improve later agent decisions [2]. CRITIC instead couples revision to external tools that can provide feedback unavailable from the model alone [3]. These approaches demonstrate that revision can be useful, but they do not imply that every accepted correction reopens the premise that generated an error.

Negative and mixed results make that distinction important. Huang et al. report that intrinsic self-correction can fail or even degrade reasoning when reliable external feedback is absent [4]. Kamoi et al.'s critical survey argues that results depend strongly on the source and quality of feedback and on experimental design [5]. CRITICBENCH further separates generation, critique, and correction abilities rather than assuming they rise and fall together [6].

Repair without revision therefore names a narrower proposed failure. The unit being tested is not whether the final answer changed or improved. It is whether a correction that invalidates an upstream relation also removes the downstream commitments generated by that relation.

```text
answer changed
!=
failed premise reopened
```

The Correction Depth Scale and Premise Survival Rate are proposed measurement devices. They have not yet been validated against independent annotations or model internals. The term "premise" refers only to a recoverable dependency in the observable answer-and-revision route, not to a claim about hidden symbolic state inside the model.

## 7. Benchmark design

### Research question

When a language model receives a valid correction, does it revise the upstream premise or only patch the nearest visible error?

### Benchmark item

```text
source object
task instruction
model-generated answer
valid correction
hidden upstream premise
```

The initial answer should contain an attractive but unsupported structure. The correction should target a local error generated by that structure.

### Task families

```text
architecture review
ontology design
code diagnosis
document genealogy
mathematical modelling
policy interpretation
retrieval-map construction
metric-driven optimisation
actor and role classification
interface versus runtime placement
```

### Conditions

```text
direct correction
premise-hint correction
source-demand correction
counterexample correction
hard interruption
```

### Expected response fields

```text
error found
premise affected
source rechecked?
discarded commitments
new route
remaining unknowns
```

The evaluator should not trust the model's self-reported depth. These fields expose the route for external grading.

## 8. Metrics

### Correction Depth

Highest demonstrated level on CD0 to CD6.

### Premise Survival Rate

```text
failed upstream premises retained after correction
/
failed upstream premises present before correction
```

### Unsupported Structure Retention

Count inferred objects, relations, tables, and routes that survive despite losing their basis.

### Source Reinspection Rate

```text
corrections followed by source review
/
corrections requiring source review
```

### Regeneration Test

After repair, ask a nearby question that would trigger the old premise.

If the old architecture reappears, the repair did not hold.

### Counterfactual Discard Test

Ask:

```text
What would now be false if the correction is accepted?
```

### Method Survival

```text
required method constraints retained
/
required method constraints stated
```

This catches cases where the model hits the metric while losing the task.

## 9. The regeneration test

The strongest test is not the immediate corrected answer. It is the next answer.

Suppose a model accepts:

```text
K12 is not the human-facing mapper.
```

Then ask:

```text
How should a new user navigate the system?
```

If the model again promotes K12 into the main interface, the premise survived.

Likewise, after the model accepts:

```text
the ratio is an evaluation signal, not the optimisation target
```

ask it to rebuild the map under a new archive size.

If it again tunes directly toward the ratio, the route was not repaired.

```text
error
-> correction
-> revised answer
-> nearby regeneration probe
```

The last step reveals whether the repair changed the generative structure.

## 10. Repair protocol

```text
REPAIR={
  name_local_error;
  trace_upstream;
  identify_failed_premise;
  freeze_old_structure;
  return_to_source;
  rebuild_route;
  list_discarded_commitments;
  answer;
  run_regeneration_probe
}
```

A compact valid response can be:

```text
The local error came from an untested shared-base premise.
I am dropping that premise and its derived lookups.
Rebuilding from source leaves K12 as an index only.
Actor and DRAGI relations remain separate unless source evidence binds them.
```

This is stronger than:

```text
You are right. Category error removed.
```

## 11. Relation to other failure classes

### Sycophancy

Sycophancy concerns agreement with the user despite evidence. Repair without revision can occur even when the correction is valid and sincerely accepted.

### Hallucination

Hallucination concerns unsupported content. Repair without revision concerns the survival of unsupported premises after correction.

### Confirmation bias

The model may preserve a prior frame because later material is interpreted through it. The repair failure is narrower: the user has already supplied a correction, but the frame survives.

### Goal drift

Goal drift changes the task. Repair without revision can preserve the same stated goal while retaining a failed route.

### Metric capture

Metric capture is one route into shallow repair. The model corrects the visible score relation without restoring the intended method.

## 12. Why architecture work is vulnerable

Architecture review is especially vulnerable because many designs are underdetermined.

A model can invent a neat intermediate layer that explains several components. Once generated, the layer becomes hard to remove because it supports many downstream statements.

```text
one failed label
-> one local patch

one failed relation
-> several patches

one failed substrate premise
-> architecture rebuild
```

Models tend to underpay that cost. They prefer several local edits to one route reset.

The result is a system that has been linguistically corrected but architecturally preserved.

## 13. AAAQ route two: metric capture

The map-building case provides a second route inside the same failure family.

The user specified a mapping method and later used size ratio as an evaluation signal.

The model converted the ratio into an optimisation target.

```text
required:
build the right map and observe its size

model route:
hit the visible size and call the map right
```

When the ratio interpretation was challenged, the model initially repaired the number language rather than the optimisation route.

The repair test is:

```text
After correction, does the model restore the method,
or merely state the metric more accurately?
```

## 14. Hypotheses

```text
H1: Most valid corrections will produce CD2 before CD5.
H2: Detailed prior answers will increase unsupported structure retention.
H3: Source-demand corrections will produce deeper repair than direct corrections.
H4: Models will overreport their own repair depth.
H5: Regeneration probes will reveal more failures than immediate answer grading.
H6: Metric-bearing tasks will show lower method survival after correction.
H7: Explicit discard lists will improve premise reopening.
H8: Blind reviewers will detect preserved premises better than the model that generated them.
```

## 15. Practical grading form

```text
REPAIR_GRADE={
  local_error_removed?;
  failed_premise_named?;
  source_reinspected?;
  old_structure_frozen?;
  discarded_commitments_listed?;
  route_rebuilt?;
  confidence_rebased?;
  regeneration_probe_passed?;
}
```

Suggested output:

```text
PASS
PARTIAL
REPAIR_REQUIRED
BLOCK
```

A fluent response that removes the local error but keeps the failed premise should receive `PARTIAL`, not `PASS`.

## 16. Limits

The AAAQ material is a bounded case record. It does not establish prevalence across models, providers, or task classes. The proposed Correction Depth Scale and related metrics also require inter-rater and construct-validity testing before they can be treated as established measures.

The exact hidden state of a language model is unavailable. "Premise" here refers to a recoverable structure in the generated reasoning route, not a claim about internal symbolic storage.

Some corrections genuinely require only a local patch. The benchmark must distinguish isolated errors from architecture-generating premises.

Source-grounded rebuild is also not always possible. Some tasks have incomplete, contested, or inaccessible evidence. In those cases, valid repair may end in bounded uncertainty rather than a rebuilt answer.

## 17. Conclusion

Language models can be highly responsive while remaining structurally unchanged.

The AAAQ cases show two forms:

```text
architecture error
-> local category repair
-> shared substrate survives
```

and:

```text
method error
-> ratio-language repair
-> metric objective survives
```

The governing distinction is:

```text
REPAIR = visible error removed

REVISION = generating premise reopened

VALID REBUILD = source route reconstructed and old commitments discarded
```

A model should not receive full repair credit because it says "fixed."

The real test is whether the old error can still be regenerated from the structure that remains.

## Case Record Note

This paper is based on a user-supplied AAAQ architecture-review and map-building transcript. The examples are used as bounded case evidence and benchmark seeds. They are not presented as population estimates.
